# `ha_uh` concordances from GloWbE

Raw KWIC exports, one file per country. Primary data: do not edit, and do not
discard. The English-Corpora wrapper is Turnstile-blocked, so these cannot be
regenerated by script.

## Naming

`ha_uh-<CC>.txt` — ISO country code as GloWbE labels it: US CA GB IE AU NZ IN
LK PK BD SG MY PH HK ZA NG GH KE TZ JM.

If a country needs more than one pull (the interface caps at 1000), suffix
them: `ha_uh-KE-1.txt`, `ha_uh-KE-2.txt`.

## Format

Whatever the interface exports. The filter only needs the surrounding context
as text on each line; it does not care about column layout.

## Processing

    python3 analysis/filter-ha-concordance.py analysis/hand-extracted/ha-concordances/ha_uh-KE.txt

Reports counts for interjection / hectare / name / unclear. The `unclear`
bucket is the only part needing a human. Accuracy was 39/40 on the labelled
validation set in `analysis/ha-labelled-validation-set.tsv`.

## How to save a pull

Saving the whole page ("Web Page, complete") works: the concordance lands in
`<name>_files/x3_*.html`, and the top-level HTML is only the frameset, so on its
own it is empty. Simpler alternative: right-click inside the results frame and
choose *This Frame → Save Frame As*, which gives the one file without the 7 MB
of assets.

`analysis/parse-glowbe-concordance.py` turns either into a TSV of
index / doc-id / country / genre / source / context.

|---|---|---|
| interjection | 446 | 44.6% |
| hectare | 478 | 47.8% |
| name | 22 | 2.2% |
| typo (space-insertion, *ha s*, *ha ve*, *Ha* for *He*) | 13 | 1.3% |
| unclear | 41 | 4.1% |

The 20-token sample of the same query gave 35% interjection against this 45%,
so sampling was unbiased but ten points out, which is what a +/-21-point
interval predicts. Precision, not bias, was the problem.

**This is bare `ha`, not `ha_uh`.** The query parameter in the saved page is
`w11=ha`. The tagged query is the one that bears on the conditioning table.
